# 作業ログ 2026-04-21

## 宇宙トラック野郎 v2 通信軽量化・状態遷移デバッグ・仕様整理

記録作成: 2026-04-21 15:19:32 JST

## 背景

宇宙トラック野郎は、当初 Rust サーバが 30fps 相当で state を WebSocket 送信し、ブラウザが受信ごとに描画する構成だった。

ゲーム要素が増えた結果、次の問題が出た。

- WebSocket payload が大きくなった。
- 通常航行中にも毎フレーム固定値や位置情報を送り続けていた。
- 通信頻度を落とすと描画がカクついた。
- クライアント側シミュレーションとサーバ側 state の責務が曖昧になった。
- デバッグ修正が続き、`game.js` と `mod.rs` の見通しが悪化した。

そのため、v2 方針として「WebSocket をフレーム同期に使わない」構造へ寄せた。

## 実施内容

### WebSocket 通信の軽量化

- WebSocket の常時 30fps state 送信を廃止した。
- 一時的に 10fps、2fps へ段階的に落としたが、描画が WebSocket 受信に依存していたためカクつきが出た。
- `ws.js` に `requestAnimationFrame` の描画ループを追加し、通信頻度と描画頻度を分離した。
- 通常航行中は、意味のない定期 state を送らない方針へ変更した。
- サーバが送る state は、ステージ開始、フェーズ変更、イベント、ゲームオーバーなどの意味があるタイミングに限定した。

### クライアント側シミュレーションへの移行

- 自機移動を JS 側へ移した。
- FUEL 消費を JS 側へ移した。
- 小惑星当たり判定を JS 側へ移した。
- 小惑星は `asteroid_plan` としてステージ開始時に一括配布し、JS 側で生成・移動するようにした。
- 鉱石は `mineral_plan` としてステージ開始時に一括配布し、JS 側で生成・移動するようにした。
- 鉱石取得時だけ `mineral_collect` として `mineral_id` と `mineral_kind` をサーバへ送るようにした。

### 通信削減に伴う不具合修正

- `launching -> playing` のフェーズ変更が届かず、自機が動かない、隕石が出ない、進行バーが進まない問題を修正した。
  - `last_sent_phase` を導入し、フェーズ変更時だけ state を送るようにした。
- サーバの古い `hp/fuel` が毎フレーム JS ローカル値を上書きし、DAMAGE/FUEL ゲージが変化しない問題を修正した。
  - FUEL/HP のサーバ同期は、補給や発進時など必要なイベント時だけに限定した。
- サーバ `tick` が進まないことで、自機点滅が消えたフレームで固定される問題を修正した。
  - JS 側に `renderTick` を持たせ、描画アニメーションをローカル tick で進めるようにした。
- 鉱石取得時に画面から消えない問題を修正した。
  - `local.minerals` から取得済み鉱石を即削除するようにした。

### ドッキング中の表示仕様整理

- BOOST/FUEL ドッキング中は、進行バー、背景星、小惑星を停止する。
- 目的地宇宙ステーションドッキング中は、右の進行バーは進める。
- 目的地ドッキング中は、背景星を停止し、小惑星を非表示にする。
- ドッキング中でも鉱石は流れてよい仕様にした。
- `routePaused` と `spaceMotionPaused` を分け、進行バー用の停止判定と背景/隕石用の停止判定を別責務にした。

### クリア画面・航路マップ遷移修正

- 配達完了画面は 10 秒後に航路マップへ進む仕様に戻した。
- 配達完了画面で WebSocket 再接続により `title` state が来ても、タイトル画面へ戻らないようにした。
- 航路マップ表示中に `ui.screen = "route"` を設定していなかったため、再接続時の `title` を無視できずスタート画面へ戻る問題があった。
- 航路マップ画面は 10 秒後に `hideRouteScreen()` を呼び、開始/続行へ進むようにした。

### コードリファイン

これにより、プラン受信、ローカル状態準備、資源同期、移動、オブジェクト更新、イベント解決、描画 state 生成を分離した。

## 2026-04-21 17:28:00 JST Game Over 後再開時のシーン残留バグ修正

### 発生していた不具合

- Game Over 後に `Try Again` でタイトルへ戻り、スタート画面から航路マップを経由して再開すると、前回の Game Over 画面やローカル描画状態が残ることがあった。
- `launching` が裏で動いているように見え、画面シーンとゲーム状態の境界が一致していなかった。
- WebSocket を軽量化し、JS 側が自機・岩石・鉱石・進行バーをローカルシミュレーションする構造にしたことで、シーン境界で JS 側状態を明示的に破棄する責務が重要になっていた。

### 原因整理

- Rust 側は GameOver 後に `restart` を受けて `title` state を返し、次の `start` で新しい `Game::new()` に入る構造だった。
- 一方で JS 側には `local`、`asteroidPlans`、`mineralPlans`、`routeConfigs`、`latestPlayState`、`requestAnimationFrame` loop など、サーバ state とは独立したローカル状態が残る余地があった。
- Game Over、Stage Clear、Route Map、Title の境界で「どのデータを捨てるか」が仕様として明確でなかった。

### 修正内容

- `app/src/truckers/js/game.js`
  - `resetClientGame()` を追加した。
  - `local`、`lastFrameMs`、`eventSeq`、`asteroidPlans`、`mineralPlans`、`routeConfigs` をまとめて破棄する。
  - シーン境界で呼び出せるよう export した。
- `app/src/truckers/js/ws.js`
  - `resetClientScene()` を追加した。
  - `stopPlayLoop()` と `resetClientGame()` をまとめ、`latestPlayState`、`lastEvent`、`prevPhase`、`lastFastScroll` も初期化する。
  - `title` state と `gameover` state 受信時に `resetClientScene()` を実行する。
  - `stage_clear` / `lap_clear` 受信時にも `resetClientGame()` を実行し、次ステージに前ステージの plan やローカル物理状態が残らないようにした。
- `app/src/truckers/js/ui.js`
  - スタートボタン押下時に `resetClientGame()` を呼ぶようにした。
  - 航路マップ表示時にも `resetClientGame()` を呼び、開始前の overlay と旧ゲーム状態を切り離した。
  - `showScreen()` で `screen-route` も明示的に非表示にするようにした。
- `app/src/truckers/mod.rs`
  - `Game::reset_runtime_objects()` を追加した。
  - Rust 側の runtime object として、岩石、鉱石、マニピュレーター長、無敵時間をまとめて破棄する。
  - `apply_client_state()` で HP 0 / FUEL 0 により GameOver へ入る前に runtime object を破棄する。
  - 目的地ドッキング成功後、スコア計算と修理/補給費計算が終わった時点で runtime object を破棄する。
  - `begin_next_stage()` でも同じ関数を使い、次ステージ開始時の初期化責務を一本化した。

### 仕様書反映

- `docs/truckers_v2.md` に `2.7 シーン境界リセット` を追加した。
- Game Over 画面仕様に、JS 側ローカル状態と Rust 側 runtime object を破棄することを追記した。
- シーケンス図に `Game Over から再開` を追加した。
- 配達完了シーケンスに runtime reset / local simulation reset を追記した。
