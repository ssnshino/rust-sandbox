# 作業ログ 2026-04-14

rust-sandbox プロジェクト初日。Pong を Rust + axum + WebSocket で実装し、モバイル操作まで整えた。

## 主な作業

### Pong 初期実装（`6464b88`）

- Rust + axum + WebSocket によるゲームサーバーの基本構成を作った
- サーバーサイドで 60fps のゲームステートを管理し、クライアントは描画・入力・音のみ担当する分離設計を採用
- フィールド 800×600、BALL_R=8、PADDLE 12×80 の定数系を固定
- ボールの打点ゾーン（端/中央で速度・角度変化）、テニスポイント方式（Love→15→30→40→Deuce→Adv→Game）を実装
- CPU AI はプレイヤーが打ち返すたびにランダムオフセットを更新して追尾する設計
- サーブ速度（SLOW/NORMAL/FAST）は `tick_count` シードの疑似乱数でランダム選択
- Web Audio API による効果音（ヒット: square 480→320Hz、スコア: sawtooth 180→60Hz）

### 2P 対戦追加（`ab403ba`）

- `/ws2p` エンドポイントで同一サーバーの 2 接続をマッチングする仕組みを追加
- `AppState` を共有して 2 つの WebSocket セッションを同期させる構成

### モバイル操作: D-pad → スライド制御へ変更（`4180541`）

- 初期実装のタッチ D-pad をやめ、Canvas スライド操作に変更
- `pointerdown` で指の Y 座標とその時点のパドル Y を記憶し、`pointermove` で移動量をゲーム座標に変換する「アンカー-デルタ方式」を採用

### スライド操作の修正（`6c3345b`）

- スライド操作を `document` 全体に貼り付けてページ外でも入力を拾えるようにした
- 指を離した後に誤入力が続くバグを修正（stop-on-idle 対応）

## 判断メモ

- サーバーサイドでゲームステートを持つ構成を選んだのは、将来の 2P 対戦での状態同期を前提にしているため
- スライド操作への変更はタッチの感触がゲームに合わないと判断したため（D-pad は位置固定で直感的でなかった）
