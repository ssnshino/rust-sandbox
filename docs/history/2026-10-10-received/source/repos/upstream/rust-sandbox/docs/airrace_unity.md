# AirRace Unity 3D 仕様書

最終更新: 2026-04-26 23:51:37 JST

## 1. 目的

`AirRace Unity 3D` は、Canvas疑似3D版 `ベクター・エアレース` の操作感とUIを、Unity WebGL上の3D GameObject構成へ段階的に移植するプロジェクトである。

現段階の最優先方針は、Unity独自の見た目を先に作ることではなく、前作の完成度が高かったHUD、操作感、ゲート表現、航路ガイドを再現すること。
Unityらしい演出や3D表現の強化は、ROUND1の基本プレイが前作相当まで整ってから追加する。

## 3. 開発・ビルド方針

- 内蔵SSDの容量を圧迫しないため、Unityプロジェクト本体は外付けSSDへ置く。
- UnityのWebGLビルドはAPFSビルド作業領域へ同期して実行し、成果物のみ `rust-sandbox` へデプロイする。
- ビルド時は不要なAppleDoubleファイルや古いWebGL成果物を掃除する。
- 大きなUI修正では、確認なしにビルドを連発しない。まずソース差分を確認し、方針が合っていることを見てからビルドする。

## 4. 現行スコープ

現行スコープは `ROUND1 チュートリアル` の完成。

- 空のUnityワールドから生成する。
- 地面、空、ゲート、パイロン、航路ガイド、スタート/ゴール滑走路をGameObjectとして配置する。
- PC、スマホ、PS4/PS5コントローラーで操作できる。
- WebGLでゲームセンターしのみ屋のメニューから起動できる形を維持する。

## 5. 操作

### 5.1 PC

- `A` / `←`: 左旋回
- `D` / `→`: 右旋回
- `W` / `↑`: 機首下げ
- `S` / `↓`: 機首上げ
- `Space`: BOOST

### 5.2 スマホ

- 左下ぷにコン左右: 旋回
- 左下ぷにコン上: 機首下げ
- 左下ぷにコン下: 機首上げ
- 右下BOOST: 加速

スマホのぷにコンはUnity標準の `OnScreenStick` を使う。
自作UIでそれっぽく作るのではなく、Unity標準入力の扱いに寄せる。

### 5.3 PS4/PS5コントローラー

- 左スティック左右: 旋回
- 左スティック上下: 機首下げ/機首上げ
- `×` / `R1`: BOOST
- `R2`: アナログBOOST

## 6. 飛行挙動

- 左右入力はロールと旋回に反映する。
- 上下入力はピッチ角に反映し、上昇/下降する。
- ピッチは垂直上昇/垂直降下でぐるんと反転しないよう制限する。
- 操作はリアル航空力学よりも、前作と同じ「遊びやすい飛行感」を優先する。
- ブースト時は速度がしっかり伸び、「ぶばーっ」と加速する気持ちよさを重視する。

## 7. ROUND1 コース

- 前作ROUND1チュートリアルの広さと難度を踏襲する。
- ゲートは丸いリングと左右パイロンで構成する。
- パイロンとゲート色は前作に寄せる。
- ゲート上にはカメラ向きのビルボード数字でゲート番号を表示する。
- 航路ガイドは球体ではなく、薄い半透明の平たいリングで表示する。
- 航路ガイドはゲート間を直線的に結ぶだけでなく、カーブに沿う滑らかな配置にする。
- ゴールは最後のゲート通過ではなく、滑走路へ着陸して完了とする。

## 8. HUD 方針

HUDはまず前作の再現を目指す。
Unity版独自のジャイロ風UIは一旦やめ、前作の見た目・情報配置・読みやすさへ寄せる。

- 上中央: ドット感のある速度数字
- 上中央やや下: 航路ガイド矢印ウインドウ
- 下中央: アナログ速度メーター
- 右側: 縦テープ式高度計
- 左上: ミニマップ
- 右下: FPS表示
- 中央付近: ROUND CLEARなどのイベントメッセージ
- 中央照準: 前作にあった `-  -` 風の前方目印

### 8.1 文字サイズ

HUD文字は基本的に大・中・小の3種類へ整理する。
ただしスマホ縦画面とPCでは視認距離が違うため、端末別テーブルを持つ。

### 8.2 航路ガイド矢印

- 前作のドット感のある矢印を再現する。
- ウインドウは角丸にする。
- `GATE n / 距離m` を表示する。
- 後方へ回り込む必要がある場合はUターン矢印を表示する。

### 8.3 背景

前作 `drawRolledBackground()` の色味と暗さを目標にする。
現状はUnityの3D画面に前作ROUND1の色を使った疑似グラデーションHUDを重ねている段階。
これは暗さと読みやすさの改善としては有効だが、水平線の傾きや高度変化への追従は未完成。

## 9. WebGL 起動仕様

- WebGL2必須。
- Chromeで「WebGL非対応」と出る場合は、Chromeのハードウェアアクセラレーション、GPUドライバ、`chrome://gpu` のWebGL状態を確認する。
- スマホではメモリ制約が強いため、WebGLビルド設定とロード時のメモリ使用量を継続監視する。
- ロード中はカスタムHTML側で進捗ログを表示する。
